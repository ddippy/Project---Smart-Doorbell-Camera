# HOME CAM — Live TFT edition

โปรเจกต์แยกสำหรับส่งภาพสดจาก ESP32-CAM มาแสดงบนจอ PCB3501S 3.5 นิ้วแนวนอน ไม่มีระบบสัมผัสและไม่มีปุ่มบนจอ แถบบนแสดงสถานะกล้อง/คำสั่ง แถบล่างแสดงโหมดและ FPS

## โฟลเดอร์

- `CAM_Sender/CAM_Sender.ino` — ESP32-CAM AI Thinker รับคำสั่งและส่งภาพสดให้ TFT; ยังมีเว็บสตรีมสำหรับมือถือที่พอร์ต 81
- `TFT_Receiver/TFT_Receiver.ino` — ESP32 DevKit + TFT, รับภาพสดและประมวลผล Telegram
- `TFT_Receiver/TFT_Secrets.h` — Wi-Fi บ้านและ Telegram config ที่ใช้อยู่
- `Arduino_Libraries/` — ไลบรารี Arduino, TFT_eSPI ที่ตั้งค่าไว้, และ TJpg_Decoder ที่ใช้ในชุดนี้

## เปิดและอัปโหลด

1. เปิด Arduino IDE แล้วเลือก `File > Open` เพื่อเปิด `CAM_Sender/CAM_Sender.ino` อัปโหลดไปยัง ESP32-CAM AI Thinker
2. เปิด `TFT_Receiver/TFT_Receiver.ino` แล้วอัปโหลดไปยัง ESP32 DevKit ที่ต่อจอ
3. วางไลบรารีจาก `Arduino_Libraries` ในโฟลเดอร์ `libraries` ของ Arduino IDE หาก IDE ยังแจ้งว่าไม่พบไลบรารี
4. เลือกบอร์ด/พอร์ต COM ที่ตรงกับแต่ละบอร์ดก่อนอัปโหลด
5. กล้องและจอเชื่อมผ่าน AP `CAM_TFT_LINK` รหัส `0641204734`; IP ของตัวรับปกติคือ `192.168.4.1`
6. เปิดสตรีมมือถือโดยเชื่อม Wi-Fi `CAM_TFT_LINK` แล้วเปิด `http://192.168.4.1:81/`

## คำสั่ง Telegram ที่คงไว้

- `/photo` — ถ่ายภาพปกติและส่งภาพที่แสดงบน TFT ไป Telegram
- `/flash` — ถ่ายพร้อมแฟลชและส่งภาพไป Telegram
- `/startsos`, `/stopsos` — เปิด/หยุด SOS ผ่านแฟลช
- `/help` — แสดงรายการคำสั่ง
- `/status` — ดูสถานะกล้อง สตรีม FPS และการส่งรูป
- `/stream` — ส่ง URL หน้า Live View
- `/reboot` — รีบูต ESP32-CAM

ตัวรับจะอ่านค่า Telegram จาก `TFT_Secrets.h`; ต้องอยู่บน Wi-Fi บ้านที่มีอินเทอร์เน็ตเพื่อใช้ Telegram ส่วนสตรีมกล้องระหว่างบอร์ดใช้ AP กล้อง-จอเหมือนเดิม

## หน้าเว็บ Live View

เชื่อมมือถือกับ Wi-Fi `CAM_TFT_LINK` แล้วเปิด `http://192.168.4.1:81/` ที่หน้าเว็บค้นหากล้องและแสดงสตรีม QVGA มีปุ่มสลับ `10 FPS · SHARE TFT` (มือถือกับ TFT ใช้กล้องร่วมกัน) และ `MAX FPS · TFT PAUSED` (หยุดเฟรมสดบน TFT เพื่อให้มือถือใช้กล้อง/เครือข่ายได้เต็มที่) พร้อมปุ่ม PHOTO, FLASH PHOTO, START/STOP SOS และ REBOOT CAM เมื่อกดถ่าย รูปจะแสดงในส่วน Captured Photo พร้อมปุ่มดาวน์โหลด และจะไม่ส่งเข้า Telegram การกดถ่ายผ่าน Telegram (`/photo` และ `/flash`) ยังคงส่งภาพเข้า Telegram ตามเดิม

รูปที่ถ่ายผ่านเว็บจะถูกเก็บในหน่วยความจำของตัวรับจนกว่าภาพพรีวิวบน TFT จะหมดอายุ (10 วินาที); หน้าเว็บเก็บสำเนาไว้ในเบราว์เซอร์แล้วจึงดาวน์โหลดภายหลังได้ ต้องอัปโหลดทั้ง `CAM_Sender.ino` และ `TFT_Receiver.ino` เวอร์ชันนี้ เพื่อให้กล้องเปิด `/whoami` สำหรับค้นหาอัตโนมัติและให้ตัวรับมีหน้าเว็บ/API รุ่นใหม่ ถ้าเปิดแล้วเว็บบอกว่าไม่พบกล้อง ให้ดู Serial Monitor ของ CAM ว่าได้ IP อะไร และตรวจว่า CAM ต่อเข้า `CAM_TFT_LINK` อยู่

## ภาพสดและการพักภาพ

TFT ใช้ QVGA 320×240, JPEG quality 14 และแสดงภาพในพื้นที่ 400×225 พิกเซลตรงกลางจอ พร้อมคิวเฟรมขนาด 1 ที่เขียนทับเฟรมเก่า จึงลดงานเขียนลงจอและไม่ไล่แสดงเฟรมค้าง การตั้ง quality 14 ส่งไฟล์เล็กลงกว่าเดิมแต่ภาพนิ่งอาจนุ่มลงเล็กน้อย ตั้งเป้าส่งได้สูงสุด 10 FPS; FPS จริงขึ้นกับ SPI, ขนาด JPEG, Wi-Fi และการใช้กล้องร่วมกับมือถือ

เมื่อมีคำสั่ง `/photo` หรือ `/flash` ตัวรับสั่งพักเฟรม TFT ก่อนถ่าย การอัปโหลด Telegram ทำงานบน task แยก เพื่อให้ลูป WebSocket และ UI ยังตอบสนอง ระหว่างนั้นภาพนิ่งยังค้างบน TFT และแถบบนแสดงสถานะส่งภาพ เมื่อส่งเสร็จจะค้างต่ออีก 10 วินาที จากนั้นจึงสั่งกล้องส่งวิดีโอต่อ สตรีมเว็บบนมือถือทำงานแยกจากการแสดงผล TFT และไม่ถูกสั่งพักด้วยคำสั่งนี้

## สายจอเดิม

- TFT `VCC` และ `GND` ต่อไฟตามชุดจ่ายไฟเดิมของจอ; ห้ามเดาแรงดันจากสีบอร์ดหรือเลขรุ่นเพียงอย่างเดียว
- `TFT_SDA/MOSI` → GPIO23; `TFT_SCK` → GPIO18; `TFT_CS` → GPIO2; `TFT_DC/RS` → GPIO21; `TFT_RESET` → GPIO4
- Touch ไม่ได้ใช้งานในโปรเจกต์นี้; การต่อสาย touch ไม่จำเป็นต่อภาพสดและคำสั่ง Telegram
- กล้องและ TFT ต้องใช้กราวด์ร่วมตามการต่อชุดเดิม

ค่า TFT_eSPI ใน `Arduino_Libraries/TFT_eSPI/User_Setup.h` ตั้งเป็น ILI9488 และ GPIO ตามข้างต้น
